# M3 — Downloaded mail for removed accounts

Five completed items provide explicit maintenance for mail retained after account removal:

1. **Bounded discovery:** list at most 64 unconfigured account IDs with cached messages or mailbox heads, in stable ID order, reporting whether more remain. The backend holds the cache gate and configuration locks while reading authoritative account IDs. A present account collection takes precedence over its preserved legacy import source; if absent, legacy accounts are read without importing/writing them. Corrupt/future configuration fails inspection rather than treating accounts as absent. Invalid cache account IDs fail closed. No automatic discovery, network request or deletion occurs.
2. **Attributable counts:** show full stable account IDs and saved header/body-preview/current-mailbox counts, including retained old-epoch headers and empty mailbox heads. These are not per-account byte estimates, email-address identities or an account recovery mechanism. No item is selected automatically. If more than 64 IDs remain, clear chosen entries and List again to reach subsequent IDs.
3. **Rechecked recovery-backed cleanup:** under the same configuration locks, re-read account IDs and refuse any target configured again before backup or deletion. The shared account-mail cleanup engine then refuses unresolved/corrupt mutation state, creates a verified whole-profile recovery snapshot, resets only the target's offline body progress and transactionally clears only its cached messages/mailbox heads and valid index documents. Failed snapshots/transactions never authorize partial mail deletion. Cancellation after a completed backup keeps the backup. Compaction failure after commit is not a failed deletion.
4. **Explicit controls and coordination:** a collapsed “Mail for removed accounts” section is available independently of account management, including when the last account was removed. List, choose an ID, request cleanup, then confirm; Keep receives initial focus and the destructive button is not default. Pending confirmation blocks account switch/add/removal. Collapsing the section cancels an idle confirmation; disclosure is disabled during active work so it cannot hide Cancel. Save current account edits first; changes invalidate confirmation. The shell pauses inbox activity and flushes the draft journal before cleanup; unreadable/unsavable drafts prevent it. Cancel and failure release maintenance; success reloads the reader locally. Clear the displayed list afterward and require explicit re-listing. The section uses the existing bounded account scroll area and is checked at 100%/200% text scale.
5. **Acceptance and lifecycle:** regressions cover old epochs, empty heads, configured exclusions, 64-ID bounds, legacy no-import reads, corrupt/future configurations, re-added accounts, indexed cleanup/restore, canceled/blocked backup, explicit selection, zero configured accounts, draft retention and maintenance release. Published application smoke checks actual control availability, discovery/confirmation, preserved active mail/draft/credential, index consistency and recovery restoration with synthetic mail only.

Cleanup keeps account settings, all active/parked drafts, recipients, navigation/offline selections, credentials, exported original/attachment files and all other accounts' downloaded mail. Only target body-progress checkpoints reset. Recovery snapshots contain the cleared mail and possibly other accounts' mail, and need their own retention policy; this is **not secure erasure**. Credentials are never exported or forgotten by these controls. No send, receive, server mutation or pending operation is replayed. Discovery counts can become stale; confirmation pins the account ID and the backend rechecks its current status, not the old count.

Missing configuration can make retained IDs unconfigured; listing never clears them automatically. This workflow does not reconstruct removed account settings or open orphan mail in an inbox. Other orphan local settings/credentials, account removal with unresolved operations, crash/power-loss/provider/other-target acceptance and renderer containment remain open. No profile schema or JSON reflection dependency is added; NativeAOT remains JavaScript-free.
