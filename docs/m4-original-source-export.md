# M4 — Original-message .eml export

Implemented 2026-11-03. Five items:

1. **Original-source contract and complete read-only retrieval.** Windows IMAP streams original octets for a full account/mailbox/UIDVALIDITY/UID key using EXAMINE, UID-scoped RFC822.SIZE and bounded BODY.PEEK. It refuses changed epochs, other-account keys, disabled accounts, messages over the available quota, and literals whose size differs from the reported size. The streaming path supports 12 MiB. The older buffered `IMailSourceReceiver` contract retains its 2 MiB limit.
2. **Strict bounded body response identity.** Check UID before or after the literal, returned partial offset, literal length, one payload, response ending and tagged completion. Reject missing/mismatched UIDs, wrong offsets, oversized/duplicate payloads and malformed framing; dispose incomplete buffers. Limit response lines. This also strengthens the shared preview body-fetch path. The parser accepts the supported UID/BODY response shapes; wider provider response compatibility remains certification work.
3. **Atomic bounded files.** `FileMessageSourceExports` saves under `<profile>/source-exports` using generated names, a cross-writer lock, same-directory staging, durable flush and a non-overwriting final move. Subjects/mailbox names never become paths. Clone caller bytes, validate identities/size, report byte count and SHA-256, and cap the directory at 64 files/128 MiB, counting leftover partial files conservatively. Existing exports are never evicted or overwritten. Require regular profile/export directories rather than directory links. No file is opened.
4. **Explicit reader controls and cancellation.** Original message (.eml) is collapsed in the ordinary bounded reader header. Download original .eml deliberately accesses the server and exposes a read-only selectable path/checksum. It does not change the decoded body, HTML preference or read flags. No automatic source fetch occurs on selection. Disabled accounts, active saved search, inbox work and storage maintenance disable/cancel the action. Account/message changes and disposal cancel it; reject late/wrong-key responses before writing. A commit just before cancellation/context loss can leave an export, but cannot repaint another reader or trigger opening. Retry is a new explicit click and may create another distinct export.
5. **Protocol, lifecycle and published coverage.** Fixtures verify exact octets, UID-before/after forms, size completeness and pre-transfer oversize rejection, framing failures, no read/server mutation, checksums, concurrent file limits, invalid/canceled writes, caller mutation while waiting, copyable controls at 100%/200% text, wrong-message/storage failure and explicit retry, stale/disposed/maintenance/account-switch cancellation. Native protocol probes retrieve/export original bytes under TLS and STARTTLS; published application smoke verifies the reader controls and cache-cleanup/backup boundary.

## Storage and scope

Exports remain on disk across restart and cache cleanup. They are **excluded from verified profile backups/restores and from the inbox-cache quota**; the controls explain this. Back up/move them separately. Their independent 64-file/128 MiB bound does not automatically remove previous exports; manage the folder explicitly. No automatic program launches, filesystem paths from mail, script execution, source rendering or server changes are introduced. An export is a separate user-created local copy; neither cache cleanup nor account removal erases it.

The 12 MiB bound includes encoded attachments. The [attachment inventory and save actions](m4-received-attachments.md) and [bounded byte viewer](m4-original-source-inspection.md) use the verified export. The [Saved originals library](m4-original-library.md) browses cataloged exports, and [local `.eml` import](m4-local-originals.md) has its own 2 MiB limit. Printing, resumable download and other-target execution are follow-ups.
