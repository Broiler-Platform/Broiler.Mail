# M4 — All-folder saved search within one account

Five completed items extend the saved-search workflow:

1. **Cross-folder keyset paging:** the optional all-folder scope searches only the current account and current cached mailbox epochs. Order is descending UTF-8/SQLite BINARY folder name, then descending UID, with exclusive full-key boundaries. Other folders' different UIDVALIDITY values are not incorrectly constrained to the cursor folder's epoch. Existing literal/FTS phrase modes, flag/body-availability/date filters and preview coverage apply unchanged. Maximum page size remains 500; no offset query or automatic receive is added.
2. **Epoch-bound continuations:** compute an account-bound SHA-256 fingerprint over a framed, sorted set of current saved folder names and epochs, at most 512 heads with names at most 1024 characters. The returned token is required for all-folder continuation and retained for previous pages/retry. Added/removed heads or an epoch change anywhere in the account reject the submitted walk with “Start a new search”. Other accounts' changes do not affect it. This is not a frozen content/flag snapshot: saved messages can change between pages, as the notice explains. Current-folder callers keep their previous epoch/UID behavior and need no token. No database schema migration is added.
3. **Explicit scope controls:** Current folder remains the default on startup/account change. Choose All saved folders for this account, then Find to submit it. Later edits do not change existing results or Next/Previous/Retry parameters. Search controls now scroll within a bounded window share so they retain room for results at 100%/200% text scale. No automatic search occurs on scope change; query/history state remains session-only.
4. **Attribution and safe reading:** cross-folder result rows show their folder and expose it in semantic labels; the reader shows folder and current account. UI row IDs now encode the full account/folder/epoch/UID, avoiding collisions where folders have identical UIDVALIDITY/UID pairs. Display prefixes never alter stored message subjects or reply data. Selecting a result reads the exact saved full key, keeps the base folder unchanged and never downloads a missing body. Receive/download/server mutations remain disabled in search. Close search restores the base folder's cached list. Account change, cancellation/disposal and queued stale results retain the existing generation guards, with explicit result/token/order validation.
5. **Acceptance:** tests cover cross-folder pages after service recreation, equal UIDs/different epochs, supplementary-Unicode binary order, literal/indexed fields and filters, changed/foreign heads, token validation, bounded head count, submitted history/edits, disabled-account search, exact cached body selection, malicious/stale/queued results and 100%/200% UI scope/attribution/layout. Published application smoke searches 502 headers across two folders with colliding epoch/UID pairs, crosses the page boundary, opens the other folder's saved body, verifies reader attribution and explains/restarts after a head epoch changes. Synthetic receiver methods throw if any network path is invoked.

Coverage remains saved sender/subject and downloaded plain-text previews only. Raw HTML, attachment text, full bodies beyond the preview bound, old epochs and server-only messages are excluded. Ordering is deterministic browsing order, not date/relevance ranking. Each all-folder page computes/validates the bounded head fingerprint; it is not a server checkpoint or authentication token. Tokens do not claim immutable message membership between pages. Indexed search still requires a valid separately rebuildable index.

This is one-account search, not a multi-account unified inbox or authoritative server search. Full-body retention/indexing, broader accessibility/provider/other-target and large-mailbox latency acceptance, synchronization/deletion reconciliation and renderer containment remain open. NativeAOT remains JavaScript-free and introduces no package dependency.
