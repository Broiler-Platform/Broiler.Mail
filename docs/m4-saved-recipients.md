# M4: five saved-recipient and completion items

Updated 2026-11-03. Five bounded parts of recipient completion are implemented in the Windows profile-backed composer:

1. **Durable account-scoped recipient book.** `recipients.json` uses the profile configuration envelope (schema 1), source-generated JSON, locked read-modify-write updates and flushed atomic replacement. Stable account IDs partition entries, including the same address saved under different accounts. There are at most 500 entries per account, 2,000 per profile and a 1 MiB file limit; whichever bound is reached first applies. Missing files start empty without being created by reading. Invalid, duplicate, oversized or newer-schema data is refused without replacement.
2. **Explicit add/update/remove management.** Expand Saved recipients in an editable draft. Enter one email address and an optional local name, then Save recipient name and address. Saving the same address (ignoring case) updates that account's entry. Select a match to edit its name/address or remove it. A changed address is a new entry; remove the old one separately. Removal changes the suggestion book only, preserving existing draft recipients. Reload supports retry after a storage error; failed initial loads disable writes until loading succeeds.
3. **Bounded local prefix suggestions.** Find saved recipient matches the start of a name or address, case-insensitively, returning at most ten entries in deterministic name/address order. A blank prefix shows the first ten. This is an explicit local picker, not an inline popup, network directory or full contact manager. It learns nothing automatically from incoming messages, sent mail, To/Cc or Bcc. Account changes clear prior results immediately and reject late results. With an existing draft, suggestions stay pinned to its sender account, even when the selected inbox account changes.
4. **Deliberate To/Cc/Bcc insertion.** Select a saved match and a destination field, then Insert selected recipient. Only the address enters the draft; the name is local suggestion metadata. Insertion appends without rewriting existing addresses, rejects an invalid existing destination field, skips a duplicate already in that field and enforces field bounds. Cc/Bcc expand to show the changed destination and focus it. Other fields, subject/body, account/From, draft ID and threading stay intact; the ordinary autosave path persists changes. Accepted, sending/unknown, closed or storage-paused drafts cannot be changed. Insertion never submits SMTP or changes submission/Sent-copy outcomes.
5. **Profile backup/restore and published AOT integration.** Windows wires the book under the selected profile root. Verified backups lock, copy, hash and validate the optional file; separate-profile restore preserves it. Cache cleanup and account removal keep saved recipients, just as downloaded account history is retained. A newly created account gets a new ID and cannot inherit a removed account's suggestions. Older backups without this optional file restore normally; restoring newer backups with it needs a build that recognizes the file. The NativeAOT published smoke exercises serialization, account isolation, insertion/autosave, backup/restore and removal, and renders the composer with the new controls.

## Validation and remaining scope

Added shared coverage checks persistence, case-insensitive upsert/removal, concurrent account updates, control/header-injection refusal, corrupt/future/duplicate files without resets, pre-cancellation, limits, prefix semantics, no Bcc harvesting, all three insertion destinations, retained identity/threading/content, invalid-field and foreign-entry refusal, submitted-state refusal, late account loads/closing, corrupt-book isolation from manual composition, UI insertion/field display and backup/restore/cache-clear behavior.

The published smoke also verifies that a corrupt book stays untouched while manual draft editing and saving remain available. The Windows published fixture additionally switches inbox accounts while retaining a draft and verifies that its saved recipients remain scoped to the original sender. All protocol fixtures remain synthetic; no real mail is sent by these checks. See [Windows x64 validation evidence](evidence/m4-five-recipient-items-win-x64/README.md).

The parent M4 multiple-drafts/recipient-completion/outbox item stays open: multiple simultaneous autosaved drafts and a visible outbox are still missing. Inline type-ahead replacement, address-book import/export or synchronization, groups, richer contact cards and broader native accessibility acceptance are future work. Other M0–M4 gaps and other-platform certification remain open. No JavaScript or new dependency is introduced.
