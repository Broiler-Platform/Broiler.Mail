# M1 — Manual selected-folder header acquisition

Five completed items extend the offline-reader workflow:

1. **Bounded explicit receiving:** receive one page of at most 50 headers from each unfinished selected folder for the enabled current account, up to eight folders/400 headers per click. Repeated Next clicks can walk beyond the 500 loaded-row limit without enlarging the visible list. Named folders use the existing read-only folder receiver; an inbox-only host supports INBOX selections. There is no automatic discovery, receiving, body download, opening, server mutation or eviction.
2. **Page integrity:** require the exact account/folder/UIDVALIDITY mailbox, bounded unique descending nonzero UIDs and compatible continuation metadata. Older pages must remain below their prior UID boundary and cover the expected page. Reject mismatched epochs, malformed/non-advancing cursors, changed membership metadata, overlap and premature continuation termination. A changed cached mailbox head during receive is rejected before save; an older walk cannot roll a new epoch back. A new first page may adopt a server's changed epoch through normal cache behavior.
3. **Save/retry checkpoints:** save each page transactionally through the existing cache before advancing its folder. Keep completed pages and retry only unfinished requests from a failed/canceled batch before moving on to another batch. Failed/disk-full saves do not advance. Attempt-scoped checkpoint updates prevent a canceled, already-committed save from changing a newer retry plan. Cancel and generation checks reject late receiver results and queued progress after account/folder changes, maintenance or disposal. A save committed just before cancellation may remain and safely counts as confirmed; unconfirmed pages can repeat harmless upserts.
4. **Reader controls:** Offline folders now has separate Receive selected-folder headers / Next, Restart selected-folder headers, and Show saved headers actions. The expanded controls scroll within a bounded share of the window so larger text does not push the inbox away. Coverage reports confirmed pages/headers, completion and the independent body-download step. Retry names the header operation; starting it transfers focus to visible Cancel at 100%/200% text scale. Show saved headers reloads the current folder locally and explicitly resets its reader; receiving alone keeps the current view. Restart keeps saved mail and makes no server request.
5. **Lifecycle and acceptance:** synthetic regressions exercise 1,101 headers, multiple folders, empty folders, failed commits/partial batches, invalid pages and continuations, epoch changes, account/folder switches, cancellation, queued results, disabled accounts and local display. Published application smoke receives and continues two folders, checks actual control availability, no-body/local-display boundaries, disabled-account reopen, verified backup/restore and cache-cleanup reset. Existing production TLS/STARTTLS protocol probes and both Windows package variants remain validation gates.

Server continuation indexes depend on the mailbox membership snapshot. They are **session-only**, never written into durable offline body checkpoints. Account/configuration or selection changes, selection Reload, and reopening reset the header walk. Restart explicitly rechecks newest arrivals after server membership/epoch changes; a changed server cursor is not automatically retried from the beginning. Ordinary maintenance retains a walk when the cache remains unchanged; recovery-backed cache clear resets it through account/cache reload. No profile schema migration is needed.

Headers are durable in the account/folder/epoch-partitioned cache and included in verified backups. Partial pages never imply server deletion. This is manual header acquisition, not an authoritative mailbox mirror: expunge reconciliation, folder rename tracking, durable server synchronization checkpoints, background scheduling and provider/platform certification remain open. The separate body batches remain at most 500 saved headers per folder per click, with durable progress. **Restart body batches explicitly to include newly received headers**; header receiving does not reset or automatically run them. General non-inline attachment retention remains separate work.
