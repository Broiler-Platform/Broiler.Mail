# M3 — Separately confirmed per-account downloaded-mail cleanup

Implemented 2026-11-03. Five items are complete:

1. **Account-specific inspection.** Manage accounts → Inspect downloaded mail reports saved headers, supported body previews and current mailbox-head counts for the selected stable account ID. Counts include retained old-epoch rows; shared SQLite bytes are deliberately not attributed to one account. Inspection does not download or delete mail, and another account's response is refused.
2. **Recovery-backed scoped deletion.** Clear this account's downloaded mail is distinct from disable/remove account and from server mailbox actions. Under the cache gate and profile configuration locks, validate pending mutation state and create a checksum-verified whole-profile recovery snapshot before deleting anything. Remove only the chosen account's headers/bodies/CID resources and mailbox heads, across all retained epochs. The backup path remains visible even if a later cancellation/deletion fails. Existing destinations, invalid profiles or incomplete snapshots never authorize deletion.
3. **Index/checkpoint isolation and retained state.** A valid attached FTS index removes only this account's documents and updates its source revision in the same transaction as deletion. Other accounts remain searchable. An unavailable/stale index keeps the existing rebuild-required behavior. Reset only the target account's offline continuation/completion before deletion, retaining all selections. If checkpoint reset wins an interruption/failing deletion, later work repeats conservatively rather than skipping cleared bodies. Other accounts' checkpoints, account configuration, all active/parked drafts, recipients, navigation, settings and credentials are kept. Optional VACUUM failure cannot turn committed deletion into an unconfirmed failure.
4. **Safe confirmation and shell coordination.** Confirmation names the captured account and initially focuses Keep downloaded mail. The destructive action is not a default button. Pending confirmation blocks account switch/removal/add and changed account details invalidate it. Before cleanup, pause inbox work and flush the draft journal; unreadable/unsavable drafts prevent cleanup. Cancel is available while running and recovery backups remain. Success reloads the reader locally; failure/cancellation releases maintenance and preserves the previous view. The controls work at 100%/200% text in the existing bounded account-management area.
5. **Recovery/fault and published acceptance.** Regression tests cover overlapping account/folder/UID identities, old epochs, valid-index preservation, backup/restore, unchanged local edits/settings, target-only checkpoint reset, invalid/pre-canceled input, cancellation after backup, existing destination, corrupt journals, unresolved mutations and an injected SQLite deletion failure. Published NativeAOT/framework-dependent synthetic checks inspect/confirm cleanup, keep an unsent draft/password/account and the other mailbox/index/checkpoint, and restore the recovery snapshot.

## Deliberate boundaries

This is explicit local downloaded-mail cleanup for an account still present in the account selector, not account deletion, secure erasure, server deletion or automatic eviction. Recovery backups keep the removed mail and may include other accounts' mail; credentials are not exported. A separate [removed-account downloaded-mail workflow](m3-orphan-downloaded-mail.md) is now available. Other orphan configuration/credential management remains open. The storage capability accepts a stable account ID and assumes its caller has quiesced receive; Windows supplies the maintenance guard and explicit confirmation. Any unresolved confirmed/uncertain operation anywhere in the profile conservatively blocks cleanup; corrupt journal state is never silently discarded. No pending server mutation or send is replayed.

The shared database/index transaction protects source and a valid attached index together; checkpoint reset is a separate conservative step before it. Process-kill/power-loss and other-target certification remain broader milestone work. NativeAOT stays JavaScript-free; renderer process containment is unchanged.
