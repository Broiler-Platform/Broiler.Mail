# M4 — Reuse saved originals after restart

Five completed items extend original-source export and its inline inspection/attachment controls:

1. **Durable receipt catalog:** successful new exports now record exact account/folder/UIDVALIDITY/UID, generated filename, length, SHA-256 and UTC save time in a versioned, atomic source-generated JSON catalog. Store filenames only, resolving paths inside the current profile. Retain at most 64 receipts and 512 KiB metadata; existing 64-file/128 MiB original-export quotas and 2 MiB individual original limit remain. The export lock serializes file-quota and catalog updates. File bytes are promoted before the receipt is published; no partially staged original is cataloged.
2. **Message-scoped listing:** List saved originals reads receipt metadata for the currently open message only, newest first. No automatic listing/selection/download occurs. Other accounts, folders, epochs and UIDs cannot appear. Old uncataloged `.eml` files remain untouched; identity is never guessed from headers or filenames. Corrupt/future/invalid catalogs fail closed and block new indexed exports without resetting old receipts. Missing/tampered files can remain listed until selected, so listing is explicitly not file verification.
3. **Verified activation and reuse:** choose one row and Use selected saved original. The existing path/directory/link/length/SHA checks re-read its bytes locally before activation. This fills the selectable source path/checksum receipt and enables the existing explicit source preview and attachment inventory/save actions. Neither is run automatically. Local reuse works when downloading is disabled, including an offline/disabled account with an available cached reader body. No server call, automatic external file launch or alternate reader window occurs.
4. **Interaction/lifecycle:** List/use starts by clearing any prior active receipt, preview and attachment inventory. Cancel, context loss, reset, new exports, disposal and queued stale callbacks cannot activate the selected row later. Failure clears the displayed inventory and requires explicit List/retry. Focus moves to lookup Cancel, then the picker/list as appropriate. Network export cancellation after file/catalog commit also refuses activation; a committed file/receipt can remain and be listed explicitly later. Controls are checked at 100%/200% text scale inside the existing source section/reader scrolling.
5. **Acceptance and retention:** regressions cover service recreation, full-key partitions, metadata validation, changed/missing originals, concurrent writes, quota reuse, old-file isolation, local UI activation, late listing/verification and post-commit cancellation. Published application smoke recreates the reader/export service, lists/uses a receipt, previews source and saves an attachment without another receiver call. The NativeAOT TLS/STARTTLS probe recreates and reads the receipt catalog after production original export.

`<profile>/source-export-catalog.json` is separate export metadata, not inbox cache/configuration. Cache cleanup retains it and the exported files. Verified profile snapshots/restores exclude it, `source-exports` and `attachment-exports`: **back these up separately together**. Relative filenames let a separate copy of catalog plus original files resolve inside a new profile directory. The catalog exposes message identities and should be protected with the exported mail.

Explicitly saving another original prunes only receipt entries whose files are missing, allowing quota reuse after manual file removal; it never deletes or evicts any file. If cancellation, disk failure or interruption wins after `.eml` promotion but before catalog commit, the complete file can remain uncataloged and still consumes the original-export quota. Existing invalid catalog data is not silently repaired or overwritten. There is no automatic adoption/reconstruction of missing metadata, arbitrary filesystem browser, catalog/file removal UI or repair workflow. An [account-scoped Saved originals library](m4-original-library.md) is now available independently of the inbox reader.

This increment reuses exports through the currently open message's reader. The separate [Saved originals library](m4-original-library.md) now removes that cache/body requirement for account-scoped catalog browsing. Arbitrary `.eml` paths, standalone open/import, general file browsing, larger originals/streaming, compose/send attachments, printing, broader provider/accessibility/other-target acceptance and renderer containment remain open. The broad `.eml` and attachment roadmap items stay unchecked. No mail-cache/profile schema migration or JavaScript is added.
