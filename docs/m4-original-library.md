# M4 — Saved originals library

Five completed items make cataloged original exports useful without an inbox body:

1. **Account-scoped catalog access:** list at most 64 existing receipted exports across the selected account's folders, epochs and UIDs, newest first. This reads the existing bounded source-generated catalog and resolves its validated generated filenames inside the profile. It does not scan/adopt arbitrary files, read source bytes, create a cache, or contact a server. Missing/corrupt/future catalog handling and export quotas remain unchanged.
2. **Standalone browsing:** Mail → Saved originals opens the library in the shell's ordinary dialog/content workflow. It is independent of cached headers, a selected inbox message or a decoded body, and works for disabled accounts. Explicit List selects nothing automatically; choose one receipt and Verify selected original. Read-only selectable details show account name/address/ID, folder, UIDVALIDITY/UID, path, bytes and SHA-256. Listing metadata never claims the file is verified. Unsupported hosts show an unavailable message.
3. **Verified inspection/extraction:** Verify uses the existing directory/path/link/length/SHA checks before creating current-key source and attachment controls. Source byte preview and attachment inventory/save are separate explicit actions; nothing is rendered, downloaded, sent, executed or opened automatically. Choosing another row disposes old details and clears their identity receipt. The library does not alter the inbox view or require original retrieval capability from the receiver.
4. **Navigation and lifecycle:** Ctrl+6 and the Mail menu use the shared shortcut definition, with existing modal/keyboard rules. Opening never starts a scan. Closing or switching accounts clears rows/details and cancels lookup, source-preview and attachment work. Uncancellable/queued old results cannot repopulate a hidden or different-account library; a new account can list while an old lookup finishes. Verification is bound to the selected receipt as well as account/generation. Cancel/failure clears unconfirmed details. The existing bounded scroll areas and Close/Cancel focus navigation support 100%/200% text scale. Shell smoke now renders the library too.
5. **Acceptance and retention:** regressions cover account/folder/epoch/UID inventory, no cache creation, disabled-account use, explicit verification/preview/extraction, read-only identity, account isolation, changed/missing files, canceled/closed/disposed/queued results, selection changes and shell Ctrl+6 close during work. Published application smoke exports synthetic mail, clears downloaded cache, then opens the library for a disabled account in an application with no inbox cache capability. It verifies source/attachment bytes, account isolation, no automatic preview, close-time clearing and separate-backup boundaries.

This library uses `<profile>/source-export-catalog.json`, `source-exports` and the existing attachment-export service. Cache cleanup keeps these exports/catalog. Verified profile backups/restores exclude them: back up the catalog and exported files separately together. Limits remain 64 original files/128 MiB plus a 512 KiB catalog, 2 MiB per original, and independent attachment quotas. An attachment save that committed just before closing/cancellation can remain; no file is opened. No file/catalog is deleted by this library.

Only the current configured account's cataloged originals are shown. Orphan/unknown account discovery for exports, arbitrary `.eml` import/open, uncataloged-file adoption, global filesystem browsing, file removal/repair, decoded standalone HTML mail reading, printing, sending attachments and larger-message streaming remain open. The existing message-scoped picker is still available. JavaScript, new dependencies, profile/cache schema migrations and renderer containment changes are not introduced.
