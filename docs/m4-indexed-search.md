# M4: five saved-text indexing items

Historical increment: 2026-11-03. The 2026-11-04 [retained-body follow-up](m4-retained-body-search.md) supersedes its preview-only coverage and advances cache/index formats to v4/v2. The original five parts were:

1. **Versioned cache revisions.** New caches use schema v3. Opening v2 creates a verified `mail-cache.db.schema-v2-<id>.backup` before adding revision state and insert/text-update/delete triggers transactionally. A v1 cache first takes its existing v1 backup and upgrades through v2. If the source quota leaves insufficient upgrade space, v2 literal reads remain available and indexing explains that the quota must be increased.
2. **Rebuildable saved-text index.** An explicit Settings rebuild creates `mail-cache.db.search.db`, using bundled SQLite FTS5 and source-generated body decoding. It indexes saved sender/subject and downloaded plain-text previews; it never receives mail or retrieves missing bodies. The optional index starts disabled. Its separate limit is 256 MiB; rebuilding can temporarily retain both old and staged indexes, plus SQLite journals.
3. **Transactional maintenance and stale detection.** Header/body saves and confirmed local MOVE/delete reconciliation maintain an attached valid index in the same SQLite transaction as the source. Keys include account, folder, UIDVALIDITY and UID. Flag/date/availability filters still read source metadata. A failed index write rolls back source changes; disabling the derived index allows a source retry. Revision mismatches reject indexed queries while literal search stays available. Uncertain server operations are never replayed by indexing.
4. **Indexed phrase controls.** Five additional field choices cover headers, sender, subject, body preview, and headers/body. They use Unicode61 case-insensitive word phrases, with accents retained. User input is always quoted and escaped as one phrase; it cannot supply FTS operators. Existing literal substring modes retain their semantics. Account/current-epoch/folder/date/read/star/body filters and exclusive-key next/previous paging apply to indexed results too.
5. **Index lifecycle controls.** Settings → Local mail storage provides Inspect, Rebuild and Disable (keep mail). Rebuild writes a unique staged database and replaces the old index only after commit and cancellation checks. Maintenance uses the existing profile/cache gate and reader/compose quiescence. Backups exclude the disposable index; a restored separate profile rebuilds from its saved source. Backed-up cache cleanup removes the index too.

The index uses a separate database with application/schema identity and revision checks. Atomic attached-database maintenance requires SQLite DELETE rollback journaling and FULL synchronous commits; another journal mode makes indexed search unavailable with guidance. Missing, stale, unsupported or corrupt indexes can be rebuilt or disabled without clearing saved messages. A failed/cancelled rebuild keeps the previous published index. An interrupted process may leave an ignored `.partial` staging file; it is never opened as the published index.

## Coverage and validation

The original increment provided **saved preview indexing**. The [follow-up](m4-retained-body-search.md) adds complete retained decoded reader text and an independent sender filter with explicit coverage. Attachments, raw HTML and unsaved/server-only messages remain excluded. Results keep existing deterministic mailbox/UID ordering, not relevance or date ranking. Old epoch rows may remain in the derived database but never appear under current mailbox heads. Large real-mailbox latency, broader accessibility and process-crash/power-loss acceptance remain wider acceptance work.

Seven added shared cases cover FTS phrase/field semantics versus literal substrings, reopening, account/epoch isolation, quoting, header/body/flag/MOVE/delete maintenance, stale/corrupt index recovery, source rollback on injected index failure, v2 backup migration, cancellation preserving the published index, and backup/restore/clear lifecycle. Published profile smoke additionally exercises FTS5 over 501 messages, next-page navigation, saved-preview matching, transactional body replacement and disable-with-mail-retained. It runs in both NativeAOT and framework-dependent packages; no JavaScript or new package dependency is introduced.

See [Windows x64 validation evidence](evidence/m4-five-index-items-win-x64/README.md). Other-target certification and remaining M0–M4 gaps are still pending.

[Account-wide saved search](m4-account-search.md) exposes optional all-folder scope with epoch-bound folder/UID paging for indexed and literal modes. Current-folder scope remains the default; this also applies to the new retained-text modes.
