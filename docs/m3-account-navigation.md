# M3 — Account start folders and pinned navigation

Implemented 2026-11-03. Five items are complete:

1. **Bounded account-scoped navigation storage.** Optional `account-navigation.json` uses the existing schema-1 envelope, source-generated strict JSON, atomic replacement and configuration write lock. At most 32 account records, eight ordered pinned folders per account, 1,024 UTF-16 characters per exact folder identity and 512 KiB total. Validate Unicode, controls, duplicates and nonempty account IDs. Mailbox strings never form filesystem paths. The default INBOX/no-pins state removes only that account's preference record. Legacy profiles need no migration or write on load. Restore is certified here with the current reader; older backup readers may reject the added file entry.
2. **Offline start-folder restoration.** Use current folder at startup explicitly saves a start folder. Startup, account switching and saved-navigation Reload load that account's current cached headers from this folder; they do not discover folders, receive headers, fetch bodies, select a message or mark it read. Unknown/renamed folders remain a local empty view until the user chooses another folder or explicitly checks the server. Disabled accounts can use local navigation. Account/generation guards reject late results and wrong-account preference responses.
3. **Pinned folder shortcuts.** Pin/unpin the current selectable folder, then choose an account-specific shortcut and press Open pinned folder. Pinned names remain available even without cached/server discovery data. A folder explicitly reported nonselectable is not opened. Pins do not select offline download folders or create/rename/delete server folders. Selecting a combo item alone does not navigate. Account changes clear/rebuild the shortcut choices; notices identify the account.
4. **Reload and reset with safe failures.** Account folders is a collapsed, bounded, keyboard-operable section, tested at 100% and 200% text. Reload saved navigation opens the saved start folder locally and closes the current reader; Reset account navigation explicitly restores INBOX/no-pins preferences while keeping the currently open folder/mail. Neither downloads nor deletes mail. Invalid/future state keeps ordinary INBOX reading and receive available but disables preference edits; repair the file and Reload. Failed saves preserve the displayed old preferences and report the unconfirmed save. An explicit save captured for an old account may finish after switching, but cannot repaint the new account.
5. **Profile and published lifecycle.** Preferences participate in the existing configuration-lock snapshot boundary, checksum verification, snapshot validation and separate-profile restore. Corrupt navigation blocks backup publication/cache cleanup, preserving mail. Cache clear keeps start/pin preferences; recovery snapshots include them. Account removal retains orphan preferences with retained downloaded mail. Windows composition wires the store; published NativeAOT and framework-dependent smoke exercises two accounts, disabled/offline navigation, controls, unpin/reset, backup/restore and cleanup without protocol calls.

These are explicit start-folder preferences, not automatic last-visited-folder history. No message body, query, credential, token or error history is stored. Explicit saves are awaited by their controls; application closure does not add a synchronous shutdown flush. No unified inbox, background per-account scheduler, OAuth, server folder rename tracking or production provider certification is implied. M3 remains open for those broader outcomes.

Validation and manifests: [Windows x64 evidence](evidence/m3-five-account-navigation-items-win-x64/README.md).

An optional [unified saved inbox](m3-unified-saved-inbox.md) now combines bounded saved INBOX headers and attributed saved-text reading across configured accounts. It does not change the active account, receive mail or expose unified write actions.
