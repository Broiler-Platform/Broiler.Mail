# Compose attachments

Compose shows its attachments below **Subject** while a draft is open. Choose **Attach file…** and pick a readable, nonempty file; each attached file is listed as its name and size with its own **Remove** button, and the quota line reads `X / 8.0 MiB · N/4 files` (plus what saved drafts leave, when that is less). A draft accepts up to four files and 8 MiB total. The active and saved drafts share a 16 MiB attachment quota and a 32 MiB draft-store limit. A file larger than the room left, or an empty one, is refused before it is read. File names are made safe for drafts: path separators, colons, control characters and emoji become `_`, and long names are shortened to 120 characters and 240 UTF-8 bytes, keeping the extension. The file dialog is a user-initiated exemption to the rule that nothing modal opens while reading or writing. A device whose file picker is not available yet (Android until UX-M5) keeps a typed path field: enter the absolute path of a regular local file and select **Add attachment**.

Adding a file copies its bytes into the draft. Autosave, parked drafts, profile backup and restore carry the copy. The original path stays out of the saved draft. Editing or deleting the source file after the copy leaves the saved attachment unchanged. While a file is read, Compose shows its bytes read beside **Cancel**; canceling, a read error, or a change of draft leaves the draft as it was. Send requires a durable submission journal. Use this or a newer build to open drafts or restore backups that use the larger attachment limits.

**Forward** of a message with attachments shows `Original message has N attachments (size).` above the attachment list with **Include original attachments**. Nothing is attached unless you choose it. Choosing it downloads the original once (or reuses a verified saved original) and adds every attachment or none, within the same four-file and 8 MiB limits; the button is disabled with the reason when they would not fit, when the draft's account is not the one the message came from, or when this mode cannot read originals. The offer is not saved with the draft: discarding, parking or resuming the draft, or ×, ends it.

**Send** while the draft mentions an attachment but has none shows an inline reminder instead of sending: **Attach file…** opens the picker and, after adding a file, moves focus to Send without sending; **Send anyway** sends once. Escape (or Back on Android) dismisses the reminder, and editing the subject or text arms it again. A pending forward offer does not trigger it. Without a file picker the first button reads **Add a file first** and moves to the typed path field.

Messages with attachments use multipart MIME with UTF-8 filenames and base64 file bytes. SMTP encodes attachments in chunks and frames DATA through an 8 KiB buffer. Large uploads display bytes sent. **Cancel send** requests cancellation. Once submission starts, cancellation may leave acceptance uncertain, and Broiler.Mail keeps the draft locked against automatic resend. IMAP Sent copies count the MIME octets before APPEND, then stream those same chunks. The draft keeps the bounded attachment bytes in memory.

The final validation passed 1,636 shared tests and 110 focused Windows tests. Loopback tests cover draft restart after deleting the source file, exact SMTP and IMAP Sent-copy attachment bytes, and private Bcc. NativeAOT package smoke verifies a 4 MiB draft attachment after profile backup and restore.
