# Consolidated roadmap status — 5 October 2026

Status after the UI round of 4–5 October 2026. This document supersedes the [4 October audit](roadmap-status-2026-10-04.md) for **current** status. The 4 October audit remains the audit baseline (implementation `d7d78d4`); its historical findings and its unchanged non-UI sections are not repeated here.

The user asked to continue the roadmap and take all UI items first. By the user's decisions, the work was done on local branches without pull requests or package publishing, and on 5 October the branches were pushed to GitHub at the user's request (the Mail branches below and the Broiler.UI and Broiler.Hosting topic and integration branches); no pull request exists yet and nothing is published; localization (the UI-14 string layer) was skipped; and fixes needed in Broiler.UI and Broiler.Hosting were prepared on local branches there and verified in Mail only with locally packed packages. No pull request numbers exist for this round.

Most of the UI-01 to UI-13 work that can be built and checked on one development machine is now implemented. What remains there needs physical devices or displays, a screen reader, the user's provider accounts, the upstream package releases, or a decision by the user. The **HTML renderer process boundary (A2)** is still the P0 release gate and was not worked on this round. Product versions 3–7 and the cross-platform phases are unchanged.

Status vocabulary (as on 4 October):

- **Delivered:** the stated implementation is present with relevant evidence. This does not imply every platform or future feature is accepted.
- **Acceptance pending:** implementation exists, but a specified real-world check remains.
- **Partial:** both implementation and acceptance work remain.
- **Open:** the required application capability is missing.
- **Deferred:** explicitly user-owned or conditional future work.

Where the work sits, used in every table below:

- **Published stack:** on `claude/ui-13-acceptance` (code tip `12ceded`; the full native runs used `4c36950`, and `12ceded` adds one composer fix, checked with the full suite and a native recheck of the composer fixtures), built against packages that are on NuGet (Broiler.UI preview.17, Broiler.Hosting preview.5). It can be merged without any upstream release.
- **Local packs:** on `claude/ui-09-upstream-adoption` (code verified natively at `e870135`; since rebased onto the published stack's tip, see the [adoption record](ui-upstream-adoption-2026-10-05.md)) and the Broiler.UI and Broiler.Hosting branches it consumes. Verified in Mail only with Broiler.UI `0.1.0-preview.18-local.7` and Broiler.Hosting `0.1.0-preview.7-local.5` from the local feed `D:\local-packages\roadmap-2026-10-04`. It needs the user to publish Broiler.UI preview.18 and Broiler.Hosting preview.7 first.
- **Open:** not done this round, often because it needs hardware or the user.

The revisions named in this document are the code that was built and tested. Documentation commits added on top of a branch change no code. Follow-ups still open (not done this round). The upstream repositories keep the detailed lists, with files and suggested fixes, on their release-candidate branches: [Broiler.UI open follow-ups](https://github.com/Broiler-Platform/Broiler.UI/blob/claude/roadmap-integration/docs/open-follow-ups-2026-10-05.md) and [release notes for preview.18](https://github.com/Broiler-Platform/Broiler.UI/blob/claude/roadmap-integration/docs/release-notes-0.1.0-preview.18.md); [Broiler.Hosting open follow-ups](https://github.com/Broiler-Platform/Broiler.Hosting/blob/claude/roadmap-integration/docs/open-follow-ups-2026-10-05.md) and [release notes for preview.7](https://github.com/Broiler-Platform/Broiler.Hosting/blob/claude/roadmap-integration/docs/release-notes-0.1.0-preview.7.md). In short:

- **Mail (cosmetic, from the fifth visual review):** in the compact reader at 640x480, when the header is capped below the Reply strip (`html-only`, `long-html`), 1 physical pixel of the next, hidden row's top border shows just above the divider, so the divider looks doubled. The cap ends exactly where that row starts; ending it 1 DIP above changes layout invariants pinned by the header tests and the 5,300-size sweep, so it is left for a separate change.
- **Mail (found while fixing the Linux CI failures of PR #15):** without message text the compact reader's header takes the whole reader but scrolls from its top. Where even the whole reader cannot hold the rows down to Retry loading (a long subject in a short window, for example 640x400 with large text), the problem and Retry stay below the visible part. A fix could scroll the header to the problem in that case.
- **Broiler.Graphics:** `FallbackSystemFont` (`src/Broiler.Graphics/Rendering/FallbackSystemFont.cs`, `KnownFontPairs` and `FontRoots()`) probes the Linux and macOS font paths on every OS. On Windows a root-relative `/usr/share/fonts/...` path resolves against the current drive, so a `usr/share/fonts` tree at the root of that drive silently replaces Segoe UI in text measurement. It should probe each candidate only on its own OS. Linux CI measures with DejaVu Sans; the Mail and Broiler.UI tests changed for PR #15 and Broiler-Platform/Broiler.UI#82 now derive their expectations from the measurer.
- **Broiler.HTML:** a sequential raster option that does not block an STA (would restore about 2× tile speed); table `max-width` squeeze at high zoom.
- **Broiler.UI:** focused-but-unselected item state; fixed heights of file/font dialog combos; `StandardCheckBox` white check on a light Highlight; format code view token colors on selection in high contrast; the toolbar's bottom border notched where the splitter meets it; scrollbar track ends under Mail's divider; in the contrast palettes, the tab focus ring on the selected header (ADR 0031) sits flush against the window's client frame, so in `high` and some palettes the ring and frame read as one thick line (cosmetic, adoption packs only, from the fifth visual review).
- **Broiler.Hosting:** a Windows `IUiTextInputHost` (per-focus IME positioning and enable); Alt chords beep; ElementAddedToSelection events.
- **Broiler.Graphics:** create-without-activation for hidden test windows; publish `FrameRendered`.
- **Broiler.Input/Hosting:** a neutral Windows input source so Mail can drop `StandardLegacyGraphicsInputAdapter`.
- **Code assurance:** regenerate `CODE-ASSURANCE.md`, `assurance.manifest.json`, and `HUMAN_REVIEW.md` (user-owned tool); they still list deleted files and lack the new units.

## Performance, 5 October

The tables, method, and limits are in the [5 October performance record](ui-performance-2026-10-05.md). It measured `main` (`757e81b`), the published branch at `f7fdb0b`, and the adoption branch at `afb0926` with UI local.6 and Hosting local.4 (since rewritten away by a rebase); the verified revisions `4c36950`, `12ceded`, and `e870135` were not measured again.

In every build, select and resize build over the proposed 8 ms at p95 and allocate over 256 KB per frame, and idle draws no frames. The adoption build is 0.3–0.4 ms slower at p50 in scroll, theme, select, and splitter and allocates 5–7 KB more per frame, and the published branch's resize is 0.8 ms slower than `main`; none of this was profiled ([observations](ui-performance-2026-10-05.md#observations)). The HTML preview's single-thread raster takes about 174 ms per tile, so frames that draw a tile take about 180–200 ms; [ADR-0005](decisions/0005-isolated-html-preview.md) measured that raster at about twice the parallel cost at 200 %.

## Decisions for the user

These were deliberately not changed:

- Light/Dark scrollbar thumb contrast (1.9–2.4:1), and whether list and scroll-view thumb colors are unified (a preset look change).
- Splitter grip contrast (2.3–2.6:1).
- Unfocused input field borders (1.3–1.4:1, up to 1.6:1 at the darkest antialiased pixels; the WCAG 1.4.11 question).
- The 0.5 DIP tolerance on Auto scrollbar visibility (Broiler.UI `claude/scroll-stop-tolerance`; sign-off requested).
- Hosting's system-palette scrollbar thumb in WindowText (WinUI uses ButtonText).
- UIA2 clients: UIAutomationCore calls SetFocus before Select, so a UIA2 Select first focuses the old row. Making SetFocus on a non-focusable item a no-op would avoid this but reverses documented behavior.
- Performance budgets and a reference machine, and whether `Measure-UI.ps1 -Strict` becomes a gate.
- Broiler.Graphics main (`FrameRendered`; unpublished and containing unreviewed changes) as the route to GPU/present timing.
- Localization languages (UI-14 was skipped this round).
- Inbox split minimums 280/400 DIP leave windows of 680–687 DIP up to 8 DIP under the readable widths; the compact threshold is unchanged, and moving it to 688 DIP needs sign-off.

Also the user's: whether to push the local branches and open pull requests, accepting Broiler.UI ADRs 0028–0034 (all still Proposed), and publishing Broiler.UI preview.18 and Broiler.Hosting preview.7.
