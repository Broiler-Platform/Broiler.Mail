# M4 — Inline inspection of a saved original-source export

Implemented 2026-11-03. Five items:

1. **Verified local reads.** The optional `IVerifiedMessageSourceExports` capability reads only a generated `.eml` filename directly inside this profile's export directory. Validate the receipt size/hash shape, regular profile/export directories and non-link file. Read at most the receipt's bounded 2 MiB length, reject changed length/extra bytes and compare SHA-256. Missing/modified files are not recreated or overwritten. Receipt/message identity is checked before any reader update. No network or credential service participates.
2. **Bounded safe byte presentation.** `OriginalSourceText` displays the first 64 KiB of original bytes, with explicit shown/total counts and truncation. ASCII text is preserved; CR/LF normalize to LF, backslashes double, and non-ASCII/control bytes appear as `\xNN`. Output is at most 256 Ki UTF-16 characters. This is not a MIME/charset/encoded-word decoder or an exact-byte clipboard representation. HTML/scripts/URLs remain ordinary selectable text; the original export stays byte-for-byte unchanged.
3. **Inline Show/Hide.** After a successful current-message export, Show saved source preview explicitly reads/verifies that file locally. Source appears in a read-only scrollable frame capped at 240 DIP inside the existing bounded reader header; no window or external program opens. Show focuses the text, Hide clears it and returns focus. No automatic read occurs after export. A new export receipt clears the old preview. Ordinary message body, HTML preference and server flags stay unchanged; source inspection does not call GetSource again.
4. **Explicit bounded clipboard copy.** Copy displayed source preview writes only the currently displayed normalized/escaped prefix to the clipboard. No clipboard reads, hidden/stale-source copy or automatic copying. Labels explain that the text may be truncated and does not reproduce original file bytes. Missing/busy clipboard feedback keeps the source and file intact. The text editor remains selectable for ordinary selection copying.
5. **Lifecycle and published acceptance.** Cancel, Hide, receipt replacement, account/message changes, disposal and queued-completion races discard old reads. A failed re-read clears old displayed data rather than presenting stale verified content. Account switching from source-text focus restores focus to the ordinary reader. Regression cases cover formatter bounds/escaping, file integrity/path/missing/cancel failures, Show/Hide at 100%/200% text, clipboard failure/no-read behavior and late/wrong-message results. Native protocol probe verifies a local export re-read under both TLS/STARTTLS fixture flows; published application smoke verifies escaped binary bytes, bounded output, explicit local inspection and Hide without additional source requests.

## Scope and storage

Inspection uses the active verified receipt in this reader. The [saved-original picker](m4-saved-originals.md) can now restore a receipted export for the same exact message after restart, without downloading it. Arbitrary `.eml` import/open remains unsupported. The full file remains independently bounded to 2 MiB; the UI is a byte-oriented prefix, not the full message/attachment viewer. When inspection is hidden or the message changes, it clears its displayed text; the exported file remains on disk.

Exports still require separate backups: profile snapshots/restores exclude `source-exports`, while cache cleanup keeps it. There is no automatic downloading, file launching, script execution, server mutation or original-cache retention policy. [Bounded received-attachment extraction](m4-received-attachments.md) is available separately. General attachment handling, arbitrary `.eml` open/import and general file browsing, printing, broader native accessibility/provider/other-target certification and renderer process containment remain open. See [original-source export](m4-original-source-export.md).
