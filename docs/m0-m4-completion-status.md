# M0–M4 completion audit

## Final M0–M4 scope

M0–M4 are complete for the bounded Windows x64 product scope. Deferred work includes renderer process isolation, Windows ARM64/Linux execution, additional live-provider certification, controlled power-loss testing, and specialized native accessibility and DPI matrices. These remain tracked follow-ups. Build manifests report renderer isolation and release readiness independently of the milestone scope.

M5 owns periodic and incremental synchronization, reconnect policy, folder-rename reconciliation across sessions, and provider OAuth. M1 meets the local manual-offline scope with a versioned profile, account-scoped saved mail, persisted body-batch checkpoints, and explicit header paging through selected folders. The complete header census retains its 4,096-message limit. M2 uses the inline reader with a selectable text alternative. M3 covers password-based multi-account use, explicit account receive jobs and recovery-backed account removal. M4 covers bounded attachments, offline search, draft recovery and original-file workflows. Direct selection in the HTML canvas, expanded orphan recovery and printing remain follow-ups. The historical audit below records the original acceptance criteria.

M2 and M3 meet the Windows x64 product scope described above. M4's bounded attachment workflow now accepts up to 8 MiB per draft and 12 MiB per received original, with transport streaming and byte progress. File-backed drafts and incremental MIME parsing beyond those limits are follow-ups. The Windows x64 package retains its existing release-readiness status until the renderer containment gate is met.

Final local checks for the reader host split and SMTP chunked MIME path passed 1,634 shared tests, 46 focused Windows tests, all three Windows x64 NativeAOT probes and self-contained package smoke. The explicit preview-zoom benchmark completed with 24 painted steps in both the managed and NativeAOT builds. Ordinary reader tests exercise the production adapter with blocked CSS, font, script, frame, media and image requests against a loopback listener.

The final attachment pass passed 1,636 shared tests, 110 focused Windows tests, all three NativeAOT probes and self-contained package smoke. Loopback IMAP verified a streamed original containing a 3 MiB attachment, readable message text, exact extraction, and rejection of a mismatched trailing UID without publication. NativeAOT probes exercised upload progress, streamed original export and exact SMTP/IMAP Sent-copy attachment bytes. NativeAOT package smoke restored a 4 MiB draft attachment from verified backup.

External acceptance requires suitable runners/devices and controlled provider/fault environments. The configured CI workflows can validate a committed/published revision, but remote results for a different revision do not certify this working tree. Renderer containment, streaming attachments, authoritative synchronization and unified views require implementation as well as tests; they are not merely missing checkmarks.

This audit accompanies actual implementation of [local-original opening/import and management](m4-local-originals.md), with regression and published smoke evidence. It does not replace the active roadmap or defer unfinished work by declaring it complete.
